# 操作系统第一课：程序到底是怎么运行起来的？

从今天开始，我们进入第二大模块：

```text
数据结构（已完成）
↓
操作系统（开始）
↓
计算机网络
↓
数据库
↓
Go Runtime
↓
分布式
↓
系统设计
```

很多程序员写了几年代码，却不知道：

```go
func main() {
    fmt.Println("Hello World")
}
```

执行时到底发生了什么。

今天这节课，我们就把这件事情彻底讲明白。

---

# 先建立一个世界观

你的电脑其实只有两个东西：

```text
CPU
内存（RAM）
```

其它东西：

```text
硬盘
网卡
键盘
鼠标
显示器
```

本质都是外设。

---

程序运行时：

```text
CPU负责计算

内存负责存数据
```

---

可以把它理解成：

```text
CPU = 厨师

内存 = 操作台
```

---

厨师：

```text
速度极快
```

---

操作台：

```text
存放材料
```

---

没有操作台：

```text
CPU什么都干不了
```

---

# Hello World 从哪里开始

假设你写：

```go
package main

import "fmt"

func main() {
    fmt.Println("Hello World")
}
```

---

执行：

```bash
go build
```

得到：

```text
hello
```

---

这个 hello 是什么？

很多初学者以为：

```text
源码
```

其实不是。

---

它已经变成：

```text
机器码
```

了。

---

例如CPU能看懂：

```text
1010101010
1101010101
1110001010
```

这样的指令。

---

所以：

```text
go源码
↓
编译器
↓
机器码
↓
可执行文件
```

---

# 点击运行发生什么

假设：

```bash
./hello
```

---

这时候：

```text
操作系统
```

出场了。

---

操作系统：

```text
Windows
Linux
macOS
```

都是。

---

它干的第一件事：

```text
创建进程
```

---

# 什么是进程

先记住一句话：

> 进程 = 运行中的程序

---

例如：

打开：

```text
微信
Chrome
GoLand
QQ
```

---

系统里：

```text
微信进程

Chrome进程

GoLand进程
```

都会出现。

---

Linux查看：

```bash
ps -ef
```

---

你会看到：

```text
PID

1234
5678
9999
```

---

每个进程都有：

```text
进程ID
```

简称：

```text
PID
```

---

# 创建进程时干了什么

操作系统会：

```text
1 创建进程对象

2 分配虚拟内存

3 加载可执行文件

4 创建主线程

5 把CPU交给它
```

---

然后：

```go
func main()
```

开始执行。

---

# 什么是内存

很多人认为：

```text
内存
=
一个大盒子
```

其实差不多。

---

例如：

你的机器：

```text
16GB RAM
```

---

意味着：

```text
16GB可存储空间
```

---

操作系统会切成：

```text
进程A

进程B

进程C
```

分别使用。

---

# 为什么程序不能直接访问物理内存

例如：

微信：

```text
地址1000
```

---

QQ：

```text
地址1000
```

---

会冲突。

---

所以出现：

```text
虚拟内存
```

---

# 虚拟内存

每个进程都会认为：

```text
自己独占整个内存
```

例如：

微信：

```text
0x00000000
~
0xFFFFFFFF
```

---

QQ：

```text
0x00000000
~
0xFFFFFFFF
```

---

看起来一样。

---

实际上：

操作系统偷偷映射：

```text
虚拟地址
↓
物理地址
```

---

例如：

```text
微信

虚拟1000
↓
物理500000
```

---

QQ：

```text
虚拟1000
↓
物理900000
```

---

这样互不影响。

---

# 为什么程序会崩溃

例如：

```go
var p *int

fmt.Println(*p)
```

---

这里：

```text
p=nil
```

---

CPU尝试访问：

```text
地址0
```

---

操作系统发现：

```text
你没有权限
```

---

直接：

```text
Segmentation Fault
```

或者：

```text
panic
```

---

# CPU怎么执行程序

CPU不会读Go代码。

CPU只认识：

```text
指令
```

例如：

```text
MOV
ADD
SUB
JMP
CALL
RET
```

---

例如：

```go
a := 1
b := 2

c := a + b
```

---

最终可能变成：

```asm
MOV AX,1

MOV BX,2

ADD AX,BX
```

---

CPU执行：

```text
取指令
↓
解码
↓
执行
```

---

不停循环。

---

这叫：

```text
Fetch
Decode
Execute
```

循环。

---

# CPU为什么这么快

CPU：

```text
3GHz
```

什么意思？

---

表示：

```text
每秒30亿次时钟周期
```

---

也就是说：

```text
1秒

≈30亿次工作机会
```

---

所以：

```text
CPU极快
```

---

# 为什么内存比CPU慢

CPU：

```text
纳秒级
```

---

内存：

```text
几十纳秒
```

---

慢几十倍。

---

所以出现：

```text
L1 Cache
L2 Cache
L3 Cache
```

---

这也是为什么：

```text
数组遍历
比链表快
```

我们之前讲过。

---

# 一个程序真的独占CPU吗

不是。

例如：

同时打开：

```text
微信

QQ

Chrome

GoLand
```

---

CPU只有：

```text
8核
```

---

怎么运行这么多程序？

---

答案：

```text
时间片轮转
```

---

例如：

```text
微信
10ms

QQ
10ms

Chrome
10ms

GoLand
10ms
```

---

切换速度极快。

---

你感觉：

```text
同时运行
```

实际上：

```text
轮流运行
```

---

```text
Go代码

编译
↓
机器码
↓
可执行文件
↓
进程
↓
CPU执行
```

---

## 2

进程：

```text
运行中的程序
```

---

## 3

CPU负责：

```text
计算
```

---

## 4

内存负责：

```text
存储数据
```

---

虚拟内存：

```text
让每个进程觉得
自己独占整个内存
```

---

操作系统负责：

```text
CPU调度
内存管理
进程管理
IO管理
```
