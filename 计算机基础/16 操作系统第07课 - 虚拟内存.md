# 操作系统第七课：虚拟内存（Virtual Memory）—— 现代操作系统最伟大的发明之一

如果让我选：

```text
Linux
TCP/IP
Git
Docker
Virtual Memory
```

哪个对程序员影响最大。

我会把：

```text
Virtual Memory
```

排进前三。

因为：

```text
Go Runtime
MySQL
Redis
JVM
Chrome
```

全部建立在它之上。

---

# 先思考一个问题

你的电脑：

```text
物理内存
16GB
```

---

但是你运行：

```go
arr := make([]byte, 100<<30)
```

也就是：

```text
100GB
```

---

为什么程序有时候能成功启动？

---

甚至：

```go
for {
    make([]byte, 1<<30)
}
```

不会立刻报错。

---

为什么？

---

答案：

```text
虚拟内存
```

---

# 没有虚拟内存的世界

假设：

```text
物理内存
```

长这样：

```text
0x0000
│
├── 操作系统
├── Chrome
├── Redis
├── MySQL
└── Go程序
```

---

每个程序直接使用：

```text
物理地址
```

---

问题来了。

---

# 问题1：程序互相干死

Chrome：

```text
0x1000
```

---

MySQL：

```text
0x2000
```

---

如果Chrome写：

```c
*(0x2000)=123;
```

---

直接改了MySQL的数据。

---

系统崩了。

---

# 问题2：内存碎片

例如：

```text
A程序
100MB
```

退出。

---

变：

```text
空闲100MB
```

---

后面：

```text
B程序
150MB
```

---

即使：

```text
总空闲内存
200MB
```

也可能放不进去。

---

因为：

```text
连续空间不足
```

---

# 问题3：程序难迁移

程序编译时：

```text
假设自己运行在

0x100000
```

---

结果：

```text
机器A
能运行

机器B
地址冲突
```

---

完蛋。

---

# 虚拟内存解决方案

操作系统说：

> 你们都别碰物理地址。

> 我给每个人发一个假的地址空间。

---

例如：

Chrome看到：

```text
0x0000
~
0xFFFFFFFF
```

---

MySQL看到：

```text
0x0000
~
0xFFFFFFFF
```

---

Go程序看到：

```text
0x0000
~
0xFFFFFFFF
```

---

注意：

大家看到的地址都一样。

---

但是：

```text
实际上不一样
```

---

# 一个经典图

```text
Chrome

虚拟地址
0x1000
   │
   ▼

物理地址
0xAA000
```

---

MySQL：

```text
虚拟地址
0x1000
   │
   ▼

物理地址
0xCC000
```

---

虽然：

```text
虚拟地址相同
```

---

但：

```text
物理地址不同
```

---

因此：

```text
进程隔离
```

实现了。

---

# 谁负责转换

CPU里面有个东西：

```text
MMU
Memory Management Unit
```

内存管理单元。

---

工作：

```text
虚拟地址
↓
物理地址
```

转换。

---

例如：

```go
x := 1
```

访问：

```text
0x123456
```

---

CPU实际上：

```text
0x123456
↓ MMU
0x8A000123
```

---

然后访问物理内存。

---

# 页（Page）

重点来了。

---

如果：

```text
每个字节都记录映射
```

---

例如：

```text
16GB
```

内存。

---

页表会大到爆炸。

---

所以：

Linux采用：

```text
分页
```

管理。

---

# 什么是页

把内存切块。

---

例如：

```text
4KB
```

一块。

---

叫：

```text
Page
页
```

---

例如：

```text
Page1
0~4095

Page2
4096~8191

Page3
8192~12287
```

---

# 页表（Page Table）

记录：

```text
虚拟页
↓
物理页
```

映射关系。

---

例如：

```text
虚拟页1
↓
物理页10

虚拟页2
↓
物理页88

虚拟页3
↓
物理页21
```

---

这张表：

```text
Page Table
```

页表。

---

# 地址转换过程

例如：

访问：

```text
0x12345
```

---

CPU：

第一步：

```text
算出页号
```

---

例如：

```text
页号 = 18
```

---

查询：

```text
页表
```

---

找到：

```text
物理页 = 200
```

---

最终：

```text
200页 + 偏移量
```

得到真实地址。

---

# 问题来了

如果每次访问内存：

```text
先查页表
再查内存
```

---

岂不是变慢？

---

# TLB

CPU工程师当然想到了。

---

TLB：

```text
Translation Lookaside Buffer
```

---

本质：

```text
地址转换缓存
```

---

例如：

刚查过：

```text
虚拟页18
↓
物理页200
```

---

缓存起来。

---

下次：

```text
直接命中TLB
```

---

不用查页表。

---

# 为什么程序能申请100GB

终于来了。

---

例如：

```go
make([]byte, 100<<30)
```

---

Linux：

```text
先给你虚拟地址
```

---

但：

```text
不分配物理内存
```

---

例如：

```text
虚拟页1
虚拟页2
虚拟页3
...
```

都先标记。

---

真正访问时：

```go
arr[0] = 1
```

---

才分配物理页。

---

这叫：

```text
Demand Paging
按需分配
```

---

# 缺页中断（Page Fault）

例如：

访问：

```text
虚拟页100
```

---

发现：

```text
没有物理页
```

对应。

---

CPU：

```text
异常
```

---

进入内核。

---

内核：

```text
申请物理页
建立映射
```

---

继续执行。

---

这个过程：

```text
Page Fault
缺页中断
```

---

# 不一定是错误

很多人误解：

```text
Fault
=
程序出错
```

---

其实：

```text
大部分Page Fault
正常现象
```

---

例如：

Go启动时。

---

就会发生大量：

```text
Minor Page Fault
```

---

# 内存不够怎么办

终于来到Swap。

---

假设：

```text
16GB
```

物理内存。

---

程序需要：

```text
20GB
```

---

Linux：

```text
把部分页写磁盘
```

---

腾出空间。

---

这块磁盘区域：

```text
Swap
```

交换区。

---

# 为什么Swap慢

内存：

```text
100ns
```

级别。

---

SSD：

```text
几十微秒
```

级别。

---

差：

```text
几百倍
~
几千倍
```

---

所以：

```text
大量Swap
=
系统卡死
```

---

# mmap

这是高级程序员必须懂的。

---

普通读取：

```text
磁盘
↓
内核缓存
↓
用户空间
```

两次拷贝。

---

mmap：

```text
文件
↓
映射虚拟内存
```

---

直接访问：

```go
data[i]
```

就像访问内存。

---

性能非常高。

---

# MySQL 为什么快

例如：

MySQL InnoDB

大量使用：

```text
mmap
页缓存
```

思想。

---

不是每次：

```text
read()
write()
```

磁盘。

---

# Copy On Write

前面讲过：

```c
fork()
```

---

父进程：

```text
10GB内存
```

---

如果直接复制：

```text
10GB
```

太慢。

---

Linux：

```text
共享页
```

---

只有修改时：

```text
真正复制
```

---

这就是：

```text
COW
Copy On Write
```

---

# Go 和虚拟内存

你以后会看到：

```go
runtime.mallocgc()
```

---

并不是：

```text
直接向系统申请每个对象
```

---

而是：

```text
一次申请大块虚拟内存
```

然后：

```text
Go自己管理
```

---

这就是：

```text
Arena
```

思想。

---

# Redis 为什么不用 Swap

Redis 官方一直强调：

```text
关闭Swap
```

---

因为：

```text
Redis
=
内存数据库
```

---

如果数据跑到磁盘：

```text
性能雪崩
```
