# 操作系统第二课：进程（Process）—— 你的程序在内存里到底长什么样

上一课我们讲：

```text
Go代码
↓
编译
↓
可执行文件
↓
进程
↓
CPU执行
```

今天我们深入研究：

> 进程到底是什么？

---

# 先纠正一个误区

很多初学者觉得：

```text
程序 = 进程
```

实际上：

```text
程序 ≠ 进程
```

---

程序：

```text
hello.exe
wechat.exe
chrome.exe
```

只是：

```text
磁盘上的文件
```

---

例如：

```bash
ls
```

看到：

```text
hello
```

它还没运行。

---

此时：

```text
不是进程
```

---

只有：

```bash
./hello
```

执行后。

操作系统创建：

```text
PID=1234
```

这时候才是：

```text
进程
```

---

# 一个程序可以对应多个进程

例如：

打开两个 Chrome：

```text
Chrome窗口1

Chrome窗口2
```

---

Linux：

```bash
ps -ef
```

可能看到：

```text
PID 1001 chrome
PID 1002 chrome
PID 1003 chrome
PID 1004 chrome
```

---

因为：

```text
一个程序
可以运行多个进程
```

---

# 进程在内存里长什么样

这是面试高频。

一个进程的虚拟内存空间：

```text
高地址
│
├───────────────┤
│     Stack     │
├───────────────┤
│               │
│               │
│               │
├───────────────┤
│      Heap     │
├───────────────┤
│ BSS Segment   │
├───────────────┤
│ Data Segment  │
├───────────────┤
│ Code Segment  │
├───────────────┤
低地址
```

记住这张图。

以后 Go Runtime、GC、协程栈全从这里展开。

---

# Code Segment（代码段）

例如：

```go
func Add(a, b int) int {
    return a + b
}
```

编译后：

```text
机器码
```

存放在：

```text
Code Segment
```

---

特点：

```text
只读
```

---

因为代码运行时一般不会修改。

---

# Data Segment（数据段）

存：

```go
var Name = "张三"
```

---

这种：

```text
已初始化全局变量
```

放这里。

---

例如：

```go
var Age = 18
```

也是。

---

# BSS Segment

存：

```go
var Count int
```

---

这种：

```text
未初始化全局变量
```

---

实际上：

```go
Count = 0
```

---

但是为了节省可执行文件大小：

```text
不写入文件
```

运行时自动清零。

---

放：

```text
BSS Segment
```

---

# Heap（堆）

终于来了。

这是程序员最熟悉的区域。

---

例如：

```go
u := &User{
    Name: "Tom",
}
```

---

通常：

```text
User对象
```

会放：

```text
Heap
```

---

特点：

```text
运行时动态申请
```

---

大小：

```text
向上增长
```

---

示意：

```text
Heap
↑↑↑↑↑↑
```

---

# Stack（栈）

函数调用用。

例如：

```go
func Add() {
    a := 1
    b := 2
}
```

---

变量：

```text
a
b
```

通常在栈上。

---

特点：

```text
自动分配
自动释放
```

---

执行：

```go
Add()
```

---

创建：

```text
栈帧(Stack Frame)
```

---

返回：

```go
return
```

---

自动销毁。

---

# 栈和堆最大的区别

## 栈

操作系统管理：

```text
自动
```

---

速度：

```text
非常快
```

---

生命周期：

```text
函数结束
立即释放
```

---

# 堆

程序申请：

```go
new()
make()
```

---

生命周期：

```text
不确定
```

---

Go需要：

```text
GC
```

回收。

---

# 一个经典面试题

```go
func Test() *int {
    a := 10
    return &a
}
```

很多初学者认为：

```text
a在栈上

函数结束

a没了
```

---

那为什么还能返回？

---

答案：

```text
逃逸分析
```

---

Go编译器发现：

```text
a被外部引用
```

---

自动放堆。

---

所以：

```go
return &a
```

合法。

---

# 什么是 PCB

每个进程都有：

```text
Process Control Block
```

简称：

```text
PCB
```

---

相当于：

```text
进程身份证
```

---

里面记录：

```text
PID

状态

寄存器

打开文件

内存信息
```

---

Linux：

```bash
/proc/1234
```

里面很多数据就来自PCB。

---

# 进程状态

经典五状态模型。

---

## New

刚创建。

```text
New
```

---

## Ready

准备好了。

等CPU。

```text
Ready
```

---

## Running

正在执行。

```text
Running
```

---

## Waiting

等待IO。

例如：

```go
http.Get(...)
```

---

等待网络。

```text
Waiting
```

---

## Terminated

结束。

```text
Exit
```

---

# 状态转换图

```text
        Ready
          │
          ▼
       Running
       /     \
      /       \
 Waiting      Exit
      ▲
      │
      └───────
```

---

# fork()

Linux最经典系统调用。

---

例如：

```c
pid = fork();
```

---

结果：

```text
父进程
    │
    └────► 子进程
```

---

神奇的是：

```text
fork返回两次
```

---

父进程：

```text
返回子PID
```

---

子进程：

```text
返回0
```

---

所以：

```c
if (fork()==0) {
    子进程逻辑
}
```

成立。

---

# 为什么 fork 很快

很多人以为：

```text
复制整个内存
```

---

如果：

```text
10GB内存
```

怎么办？

---

Linux用了：

```text
Copy On Write
COW
```

写时复制。

---

初始：

```text
父子共享内存
```

---

只有修改时：

```text
真正复制
```

---

非常快。

---

# exec()

fork后通常：

```c
exec(...)
```

---

作用：

```text
替换当前进程代码
```

---

例如：

```text
bash
↓
exec ls
```

---

变成：

```text
ls进程
```

---

# fork + exec

Linux创建新程序：

本质：

```text
fork
↓
exec
```

---

这两个必须记住。

面试经常问。

---

# 僵尸进程（Zombie）

进程结束：

```text
代码执行完
```

---

但父进程：

```text
没调用wait()
```

---

PCB还保留。

---

状态：

```text
Zombie
```

---

查看：

```bash
ps aux
```

看到：

```text
Z
```

---

就是僵尸进程。

---

# 为什么要保留

因为父进程要知道：

```text
退出码
```

---

例如：

```text
成功？

失败？

崩溃？
```

---

# 孤儿进程

反过来。

父进程死了。

子进程还活着。

---

例如：

```text
Parent
  │
  └── Child
```

---

Parent退出。

---

Child变：

```text
Orphan
```

孤儿进程。

---

Linux会让：

```text
PID 1
```

接管。

---

现代Linux：

通常：

```text
systemd
```

---

# 为什么 kill -9 能杀进程

例如：

```bash
kill -9 1234
```

---

其实：

```text
发送SIGKILL
```

信号。

---

内核收到：

```text
直接终止
```

---

所以：

```text
无法捕获
无法忽略
```

---

# 为什么 Linux 说万物皆文件

例如：

```text
磁盘

网卡

Socket

管道

键盘
```

---

内核统一抽象：

```text
File
```

---

所以：

```c
read()
write()
```

都能操作。

---

后面讲：

```text
Socket
epoll
```

你会看到这个设计有多牛。
