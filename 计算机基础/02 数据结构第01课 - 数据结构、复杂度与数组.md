# 第一课：什么是数据结构

很多初学者认为：

```text
数组
链表
树
```

就是数据结构。

其实不是。

## 数据结构的本质

一句话：

> 数据结构 = 如何组织数据

例如：

你有 100 万用户。

```text
张三
李四
王五
赵六
...
```

怎么存？

有很多方案：

```text
挨个排队
```

```text
形成链条
```

```text
形成树状
```

```text
做成哈希表
```

不同组织方式：

```text
查询速度
插入速度
删除速度
内存占用
```

完全不同。

---

# 为什么需要数据结构

假设：

```go
users := []string{
    "张三",
    "李四",
    "王五",
}
```

查找：

```go
for _, u := range users {
    if u == "王五" {
        return
    }
}
```

如果：

```text
3个用户
```

没问题。

---

如果：

```text
1000万用户
```

呢？

就变成：

```text
张三？
不是

李四？
不是

王五？
不是

...
```

一个一个找。

这叫：

```text
线性查找
```

复杂度：

```text
O(n)
```

很慢。

---

于是人们开始思考：

```text
有没有更快的方法？
```

于是：

```text
树
Hash表
```

诞生了。

---

# 什么是时间复杂度

这是整个数据结构课程最重要的概念。

## O(1)

无论多少数据都一样快

例如：

```go
arr := []int{10,20,30}

fmt.Println(arr[1])
```

CPU：

```text
直接取第二个位置
```

时间固定。

叫：

```text
O(1)
```

---

## O(n)

例如：

```go
for _, v := range arr {
}
```

遍历。

数据翻倍：

```text
时间翻倍
```

叫：

```text
O(n)
```

---

## O(log n)

例如：

```text
100万数据

查20次找到
```

而不是：

```text
查100万次
```

树结构经常出现。

---

# 第一种数据结构：数组

## 数组的本质

很多人认为：

```go
[]int
```

是数组。

其实不是。

Go里：

```go
[10]int
```

才是真数组。

---

底层内存：

```text
地址

1000 -> 10
1004 -> 20
1008 -> 30
1012 -> 40
```

连续存储。

---

# 为什么数组查询快

假设：

```go
arr := [4]int{
    10,
    20,
    30,
    40,
}
```

取：

```go
arr[2]
```

CPU直接算：

```text
起始地址
+
2 × 元素大小
```

得到：

```text
1000 + 2×4
=
1008
```

直接找到。

不用遍历。

所以：

```text
O(1)
```

---

# 数组的缺点

插入慢。

例如：

```text
10
20
30
40
```

插入：

```text
25
```

变成：

```text
10
20
25
30
40
```

必须搬家：

```text
30右移
40右移
```

所以：

```text
O(n)
```

---

# Go中的Slice

你天天用：

```go
[]int
```

实际上：

```go
type slice struct {
    ptr
    len
    cap
}
```

大概长这样。

---

例如：

```go
s := []int{1,2,3}
```

内存：

```text
slice

ptr ─────┐
len = 3  │
cap = 3  │
         ↓

[1][2][3]
```

---

# append为什么快

```go
s := make([]int, 0, 8)
```

容量：

```text
8
```

长度：

```text
0
```

插入：

```go
append(s,1)
```

只是：

```text
len++
```

几乎不搬家。

---

# append为什么会扩容

假设：

```text
len=8
cap=8
```

再插入：

```go
append(s,9)
```

空间没了。

Runtime：

```text
申请更大数组

复制旧数据

释放旧数组
```

这叫：

```text
扩容
```

---

# 为什么扩容不是每次+1

假设：

```text
1
2
3
4
...
```

如果每次：

```text
+1
```

会复制：

```text
1次
2次
3次
4次
...
```

极其慢。

所以 Go 采用：

```text
1
2
4
8
16
32
64
...
```

指数扩容。

---

# 面试题：slice传参为什么会修改原数组

例如：

```go
func test(s []int) {
    s[0] = 999
}
```

调用：

```go
arr := []int{1,2,3}

test(arr)
```

结果：

```go
[999,2,3]
```

为什么？

因为传过去的是：

```text
ptr
len
cap
```

而不是复制整个数组。

---

# 为什么Redis不用数组存所有Key

假设：

```text
1000万用户
```

查：

```text
user_8888888
```

数组只能：

```text
一个一个找
```

复杂度：

```text
O(n)
```

太慢。

所以 Redis 使用：

```text
HashTable
```

后面会讲。
