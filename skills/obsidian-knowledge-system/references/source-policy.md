# Source policy

## Preferred sources

1. Official documentation.
2. Official release notes and migration guides.
3. Primary source repositories.
4. High-quality engineering write-ups, clearly marked as secondary.

## Research workflow

- Use `find-docs`/Context7 for libraries, frameworks, SDKs and APIs.
- Use official sources for product behavior and version-specific commands.
- Record URLs and retrieval dates.
- Separate sourced facts from recommendations.

## Uncertainty

If a source cannot be fetched or the behavior is version-dependent, say so in the note. Do not fabricate a command, flag or API signature.

## Copying

Summarize and restructure. Do not reproduce long passages. Use short quotations only when the exact wording matters.
